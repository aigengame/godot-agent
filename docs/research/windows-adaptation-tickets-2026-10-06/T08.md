## Design reference

#1109 (native parent for scope/progress; only Blocked by defines execution prerequisites).

## What to build

Start/status/stop a per-project Windows daemon through real CLI/MCP paths using loopback endpoints, private discovery, a stable lock and detached lifetime. Running does not mean an Engine session is ready.

## Acceptance criteria

- [ ] Retain two bound 127.0.0.1:0 listeners before atomic publication. Concurrent starts have one winner, losers/stale recovery cannot overwrite it, and two projects stay isolated.
- [ ] Use a separate stable msvcrt lock with readable metadata; acquire before recovery/publication, release last and never unlink the lock. Create a new private mode-0o700 directory and narrowly check/reject unsafe existing directories.
- [ ] Authenticate peers before live/control requests; wrong/absent auth cannot obtain service/stop it. Bound silent/malformed connections by existing absolute deadlines; keep secrets out of schema/results/logs.
- [ ] Both normal CLI exit and parent terminal/IDE closure leave the daemon usable; disclose host Job limits if detachment cannot be met. Status/stop/stale recovery and failed-start rollback work.
- [ ] Keep Unix socket_path intact and allow null on Windows; add one optional transport/address endpoint DTO without secrets. Convert at the command surface, never import daemon endpoint types into core contracts.
- [ ] Record a Windows transport/discovery ADR and narrowly amend ADR-0021. Keep support/runtime/schema/help aligned through the single static predicate; unimplemented session/windowed paths fail explicitly.
- [ ] Relevant Unix UDS/flock/lifecycle and current import-direction checks pass.

## Scope boundary

No fixed port, scan, remote IPC/TLS, ACL framework, PlatformService or core-to-daemon dependency.

## Delivery constraints

Follow the overall design reference and ADR-0045 at the merged core-layering revision. Add small adapters at existing seams; keep core closed, framework-free and process-entry-free, and gda-mcp on the public CLI ABI. Preserve the existing import-direction gate, RunResult, EngineSession.request, Value projection and completed-run settlement.

Use UTF-8 at the source. Windows CI, code-page compatibility, platform/provider registries, broad core refactoring and Windows handler copies are excluded. Update affected schema/help/docs/configuration/bundled skill with the behavior. Save commands, environment, exact test counts, skip reasons and raw results. Real public-channel evidence and relevant Unix regression checks are required; mocks alone do not establish integration.
